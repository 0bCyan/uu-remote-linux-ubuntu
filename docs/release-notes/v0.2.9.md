修复 H.265 + VAAPI 时手机卡在「正在传输」；VAAPI 可选加大编码缓冲。/ Fix H.265 + VAAPI stalling at "transferring"; optional VAAPI VBV buffer.

### 修复 / Fixed
- **H.265 用 VAAPI 硬件编码时没有画面**（#48，感谢 @NuoFang6）：`hevc_vaapi` 只在关键帧处写帧分隔符，主机按分隔符切帧，
  把整组画面当成一帧后全部被拦下，被控端几乎不发画面，手机停在「正在传输」。现在按图像边界切分 H.265 访问单元，
  不再依赖帧分隔符；维护者补充了后缀 SEI 等尾随单元的处理。
  已实测：作者在 Intel 核显 + 官方安卓客户端上（2560×1440，约 58 fps）；维护者在 RTX 3090 上用固定输入探针验证
  `hevc_nvenc` 与 `libx265` 均 90/90 帧可解码、首帧为关键帧。
- H.265 access units are now split on picture boundaries (RFC 7798), fixing hevc_vaapi sessions that sent almost nothing.

### 新增 / Added
- **`UU_VAAPI_BUFFER_MS`**（#47，感谢 @NuoFang6，源自 #42）：可选加大 VAAPI 的编码缓冲（10–1000 ms），缓解高分辨率下
  关键帧被压糊、画面周期性模糊。默认不启用。⚠️ 仅在一台机器上实测，代价是关键帧变大，建议从 250 ms 试起。
- Optional VAAPI VBV buffer `UU_VAAPI_BUFFER_MS` (off by default; verified on one machine only).
