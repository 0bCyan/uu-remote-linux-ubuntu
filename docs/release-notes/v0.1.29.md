### 修复 / Fixed
- **GNOME Wayland（Portal）锁屏冷连接**（#28，感谢 @wanglz111，#30）：服务在已解锁时启动、随后锁屏，再从客户端连接时，
  以前因为 Portal 无法创建而整个连接被丢弃，无法远程自动解锁。现在先建立控制通道、上报锁屏状态并处理「自动解锁被控端」，
  Portal 就绪后再恢复画面、输入和剪贴板；锁屏期间不发画面、不注入桌面输入，并唤醒显示器（不会解锁）。
  官方 **Mac 客户端**已实机验证（锁屏 → 连接 → 自动解锁 → 画面和输入恢复）。
- **iPhone 锁屏冷连接自动解锁**（#29，感谢 @wanglz111，#34）：iPhone 4.42.0 要先收到视频帧才会发起自动解锁。Portal 等待就绪且
  确认锁屏时，主机每秒在已协商的视频轨上发一帧生成的黑画面（需 FFmpeg 带 libx264/libx265），解锁后由真实画面接续。
  贡献者用同一二进制做了 开→关→开 对照，iPhone 4.42.0 + H.265 实机通过；⚠️ H.264 手机实机、其他客户端版本、慢速中继未验收。
  黑帧不是真实锁屏画面，锁屏界面不能操作键鼠；未开启「自动解锁被控端」时无法远程解锁（控制中心 → 安全 → 自动解锁被控端）。
  Locked cold connections on GNOME Wayland now establish CONTROL first and support auto unlock (Mac verified); black video
  while locked lets iPhone 4.42.0 start auto unlock (H.265 verified by the contributor).
- 断开事件只关闭对应 `ice_id` 的连接，不再误关同时打开的文件传输、终端、端口映射连接。
  Releases close only the matching peer; tool peers stay open.
- X11 主机回归：控制通道处理改动后，已在 X11 + NVENC 主机上实测连接、Echo、锁屏状态上报和画面；画质切换由自动化测试覆盖。
