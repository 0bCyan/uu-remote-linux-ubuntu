VAAPI 硬件编码、虚拟声卡、无人登录的虚拟桌面和 Arch/Omarchy 支持。/ VAAPI encoding, virtual audio sink, linger virtual desktop, Arch/Omarchy.

### 新增 / Added
- **VAAPI 硬件编码（Intel/AMD）**：`UU_VIDEO_ENCODER=vaapi`（`UU_VAAPI_DEVICE` 默认 `/dev/dri/renderD128`），需要显式开启，不会自动选择；
  初始化失败时自动回退 CPU 编码。✅ Intel UHD 770（iHD 驱动）实机验收：用官方 Mac 控制端测试了各档画质、30/60 帧、缩放和重连，
  全程硬件编码，CPU 占用比 libx264 低约 40%。⚠️ AMD 显卡、`--features inproc-av` 管线的 VAAPI 尚未实机验证。
  Opt-in VAAPI with CPU fallback. Accepted on Intel UHD 770; AMD and the inproc-av path are not hardware-verified.
- **虚拟声卡（静音运行）**：开启「静音运行」时创建虚拟输出 `uu-remote-sink`，把声音转到它上面采集，本机扬声器静音、控制端照常有声；
  结束后恢复原默认输出；异常退出后下次启动自动清理。有 `pactl` 时用它，没有时（默认的 Ubuntu 桌面）用 PipeWire 自带的 `pw-cli`/`wpctl`。
  ✅ Ubuntu 24.04（PipeWire 1.0.5）上用官方 Mac 控制端验收：开关、断开恢复、多工具连接，以及强杀后的恢复。
  Virtual null sink while muted (pactl or PipeWire-native). Accepted on Ubuntu 24.04 with the official Mac viewer.
- **虚拟桌面改进**：默认使用 linger 用户总线，并导入 `DISPLAY`/`XAUTHORITY`，D-Bus 激活的程序（如 GNOME Terminal）也会出现在虚拟屏幕上；
  独立的 X 认证 cookie、`Type=notify` 就绪通知、退出清理；Xvfb 被强杀后残留的显示器文件会自动清理。
  ✅ 虚拟机里验证了无人登录开机上线、GNOME Terminal 出现在 `:99`、键鼠；残留清理在实机验证。
  ⚠️ 无人登录场景下尚未用官方控制端完成验收（清单见 `contrib/virtual-desktop/ACCEPTANCE.md`）。
- **Arch Linux / Omarchy**：README 增加 pacman 依赖和 Omarchy（Hyprland）说明。✅ 虚拟机里 Hyprland 截屏、uinput 键鼠、剪贴板通过。
  ⚠️ 尚未在真实 Omarchy 上用官方控制端验收；相对鼠标位移的精确像素没有验证。
- **KMS 截屏（实验原型，默认不编译）**：`--features kms` + `UU_DESKTOP_BACKEND=kms`，需要 `cap_sys_admin`。
  ❌ 虚拟机里登录界面截图全黑，视觉验收未通过；**不支持**锁屏/登录界面，发布包里也不包含这个功能。说明见 `docs/validation/kms.md`。

### 修复 / Fixed
- 虚拟声卡恢复时，如果原默认声卡已经不存在（比如 USB 声卡被拔掉），不再留下虚拟输出作为默认。
- 「静音运行」相关的日志会区分虚拟输出和真实声卡的静音状态。

### 未改变 / Unchanged
