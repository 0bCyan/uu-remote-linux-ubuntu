### 修复 / Fixed
- **服务运行中桌面分辨率变化后，新连接一直停在「正在传输画面」**（#18，感谢 @liangjiahui01）：每次建立桌面连接前重新读取
  X11 桌面尺寸，变化时重建截屏；截屏尺寸不符时报明确错误，不再误报「HEVC unavailable」。
  已在隔离 Xvfb 上用 `xrandr` 改尺寸验证；xrdp 场景未实测。连接期间改分辨率暂不支持（需重连）。
  X11 now re-reads the desktop size before each connection, so a RandR/xrdp resize no longer stalls new connections.
- **终端接回**（#17 后续）：修复延迟恢复尺寸可能覆盖新尺寸的竞态，以及接回时同一段输出既在回放里又被实时重发的问题。
  Fixed a size-restore race and duplicated output on terminal reattach.

### 改进 / Improved
- **原生 Wayland 采集**（#16，感谢 @meotao 的实机测量）：采集进程直接写入 FFmpeg，不再经主进程中转 4K 帧；采集与写管道
  双线程交替，管道缓冲扩大；SHM 截屏缓冲复用，不再每帧分配。
  ⚠️ 只做了编译和单元测试，没有在真机上测到提速效果；请求高帧率时的实际帧率欢迎在 #16 反馈。
  Native Wayland: capture pipes straight into FFmpeg, overlaps capture with writes and reuses SHM buffers. Not yet
  measured on real hardware.
- 视频统计日志新增本窗口的 `window_s`、`window_sent`、`window_skipped`（原 `sent`/`skipped` 仍为累计值）。
  The latest-frame stats line adds per-window counts.
