修复大分辨率 CPU 编码时画面周期性变灰，以及非 NVIDIA 机器上每次建流都白跑一次 NVENC。/ Fixes grey keyframes on large CPU-encoded desktops and needless NVENC attempts on non-NVIDIA hosts.

### 修复 / Fixed
- **大分辨率 CPU 编码画面周期性变灰**（#8，感谢 @liangjiahui01 的详细分析）：libx264 的 VBV 缓冲原来最多 500 kbit，
  3296×2036 这类大屏的关键帧放不下，x264 只能输出近乎纯灰的关键帧再逐步补清晰。现在 CPU 编码的缓冲改为 1 秒的码率
  （500k～8000k），NVENC 和 VAAPI 不变。用 3296×2036 静态画面、高清 2M 档复现验证：原来每个关键帧都变灰，修复后不再出现。
  x264 VBV buffer is now one second of bitrate; NVENC/VAAPI unchanged.
- **非 NVIDIA 机器每次建流都先试一次 NVENC**（#10，感谢 @hiclaw）：`ffmpeg -encoders` 在没有 N 卡时也会列出 `h264_nvenc`，
  所以以前 AMD/Intel 机器上每次连接或切换画质都会先启动一个注定失败的 NVENC 编码。现在未设置 `UU_VIDEO_ENCODER` 时，
  只有检测到 NVIDIA 驱动才尝试 NVENC，否则直接用 CPU 编码；新增 `UU_VIDEO_ENCODER=nvenc` 可以强制使用。
  NVENC is only tried when an NVIDIA driver is present; `UU_VIDEO_ENCODER=nvenc` forces it.
