控制端：GNOME Wayland 下剪贴板不再让 Dock 图标跳动。/ Viewer: clipboard no longer makes GNOME Wayland Dock icons jump.

### 控制端修复 / Viewer — fixed
- **GNOME Wayland 剪贴板与 Dock 跳动**（#37，感谢 @wanglz111，#41）：之前每 500 ms 调用一次 `wl-paste`，在缺少 data-control 的 GNOME 上
  每次都会创建临时窗口，导致 Dock 图标持续跳动。现在桌面窗口直接通过 SDL 读写文本剪贴板，不再需要 `wl-clipboard` / `xclip`。
  只在桌面窗口获得焦点时同步，仍保留 30 KiB 上限、`UU_VIEWER_CLIPBOARD=0` 关闭开关和原有协议。
  早期版本已由报告者在 GNOME Wayland 实机确认 Dock 不再跳动；⚠️ 最终的焦点门控版本只有自动化测试，尚未重新实机验收。
  Clipboard now goes through the existing SDL window (focused only). An earlier revision was confirmed live by the reporter;
  the final focus-gated revision is covered by automated tests only.

### 已知问题 / Known issues
- 剪贴板只在控制端窗口获得焦点时同步；窗口在后台时收到的被控端剪贴板变化不会写入本机。
- 剪贴板内容提供方响应很慢时，可能短暂卡住控制端窗口（SDL2 同步读取）。
- 控制端 → 官方 Windows 被控端的剪贴板：被控端确认收到文本，但未出现在其桌面剪贴板中，仍在排查；与官方 Mac 被控端的双向剪贴板未验证。
- Clipboard syncs only while the viewer window is focused; viewer → official Windows host clipboard is still unresolved.
