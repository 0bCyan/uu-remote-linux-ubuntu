修复缩放桌面尺寸为奇数时画面一直「正在传输」。/ Fix the stream never starting when the captured desktop has an odd size.

### 修复 / Fixed
- **奇数尺寸桌面无法出画面**（#53，感谢 @wen0531）：KDE Plasma（Wayland，门户后端）150% 缩放、两块屏上下排列时，
  逻辑桌面为 2560x2507，H.264/HEVC 编码器要求偶数宽高，全部启动失败，客户端一直停在「正在传输画面」。
  现在原生分辨率采集遇到奇数宽高时，在右/下补齐 1 像素黑边再编码；偶数尺寸、「其他分辨率」缩放不受影响。
  贡献者已在 KDE Plasma 6.7 / Wayland / NVENC + 官方安卓客户端上实测。进程内编码（`inproc-av`）路径未覆盖。
- When the native capture size is odd (e.g. scaled stacked monitors), the encoder input is padded by one black
  row/column so every H.264/HEVC encoder can open. Verified by the contributor on KDE Plasma 6.7 (Wayland, NVENC).
  The optional `inproc-av` path is not covered.
