修复终端接回错位、低码率 CPU 编码灰屏、niri 无法建流。/ Terminal reattach, low-bitrate CPU encoding and niri fixes.

### 修复 / Fixed
- **终端接回后全屏程序画面错位**（#17）：接回已有会话时，主机先把终端行数临时减一、稍后恢复，触发 tmux、vim、
  Claude Code 等全屏程序整屏重画。
  ⚠️ 已通过单元测试；尚未用 Android 客户端实机验证，如仍错位请在 #17 反馈。
  Reattaching a terminal session now nudges the PTY size so full-screen programs repaint. Unit-tested; not yet
  verified with the Android viewer.
- **低码率档周期性灰屏**（#15，感谢 @mengdehong）：外部 FFmpeg 的 CPU 编码（libx264，以及同样处理的 libx265）在
  码率档（原画 / 超清 / 高清 / 自定义）改用平均码率（ABR），避免 4K 低码率下关键帧耗尽缓冲而发灰；「自动」档仍用 CRF。
  libx264 修复由贡献者在 Android 客户端实测；libx265 只验证了参数可用。
  CPU encoding uses ABR for bitrate presets (CRF for Auto), fixing gray keyframes at 4K and low bitrates.
- **niri 等合成器无法建流**（#15）：原生 Wayland 后端在合成器没有 `wlr-output-power-management` 时跳过唤醒屏幕，
  不再中断采集。Capture continues when the compositor lacks output power management.

### 文档 / Docs
- Wayland 会话的 systemd 单元写法、uinput 模块开机加载（#16，感谢 @meotao 的实机测量与建议）；未编入 `wayland`
  特性时的报错改为明确提示重新编译。
  Wayland systemd unit, uinput autoload, and a clearer error when the binary lacks the `wayland` feature.
