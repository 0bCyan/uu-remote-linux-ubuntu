扫码登录改为与官方客户端一致，修复二维码刚生成就失效。/ QR sign-in now matches the official client.

### 修复 / Fixed
- **登录二维码反复立即失效（1190）**（#68，感谢 @axlrose 的详细排查）：逆向官方 Mac 客户端（4.42）后确认，新版服务端在生成二维码时
  返回 `status_query_ticket`，官方客户端查询扫码状态和确认登录时都用它（放在 `token` 键下）；我们此前优先发送旧的 `token` 字段。现在与官方一致：
  - 生成二维码不带请求体；状态查询用 `status_query_ticket`（服务端没有时才用旧 `token`）；
  - 状态查询是长轮询，每次应答后立即再问，单次超时 60 秒（此前 12 秒）；
  - 状态 3 立即换新码、状态 0 在 0.35 秒后换新码、状态 4 登录（状态 3 不再去调确认登录）；
  - 出错（如 HTTP 400 / 1190）或超时时停止轮询，等用户点击登录窗口新增的「刷新二维码」按钮（终端里按回车；既无窗口也无终端时 60 秒后自动换码）。
  取代 v0.2.19 的临时退避和「重新注册设备」提示。已用全新设备身份实测：状态查询正常挂起，60 秒后按官方行为停止并等待刷新；
  未在 #68 那台被标记的设备上实测，「刷新二维码」按钮的界面尚未在桌面上目视验收。
- QR sign-in mirrors the official Mac client: `status_query_ticket` as the status ticket, 60 s long poll, regenerate on status 3/0,
  stop on errors (e.g. code 1190) until the user clicks the new “refresh QR” button.
